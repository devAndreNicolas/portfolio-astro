# Spec-driven development

Before material user-facing, data-model, or workflow work, add a numbered folder here with:

1. `spec.md` — user outcome, non-goals, acceptance criteria, risks.
2. `plan.md` — seams, implementation decisions, verification approach.
3. `tasks.md` — ordered, independently verifiable tasks.

Specs describe behavior, not an agent's hidden reasoning. Small typo fixes and isolated copy corrections do not require a new spec.
